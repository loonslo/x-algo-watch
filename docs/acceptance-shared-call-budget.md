# 跨工作流共享调用预算核对

维护及验收日期：2026-10-28。环境：Windows / Python 3.14.0。本次是本地实现、模拟传输回归和现有 GitHub 产物的只读核对；未调用新模型、推送、启动远程工作流或部署。

## 需求与实际边界

主链已保存的审计不足以证明完整日预算：只读样例未合并、发布冲突或发布失败时，请求仍可能发生。新增 call_budget.py，在模型请求前核对两个可信工作流的运行及每次重跑，并取回独立请求账本。只导入请求编号及 UTC 日期用于计数，不导入正文、结论、阶段缓存或检查进度。

- check.yml 与 sample.yml 共用原串行锁；模型任务增加 actions: read，只读运行和产物。模型密钥仍只在起草步骤可见，样例任务仍无内容写权限。
- 不按创建日期过滤运行，避免漏掉今天重跑的旧运行；逐次读取尝试。只接受本仓库 main、既有两个工作流及允许的触发类型；样例另要求所有者。
- 每次请求发出前原子写入 call-ledger.json，再进行网络请求。旧研究链和新机制链都接同一钩子。独立账本按运行及尝试命名，在失败后也尝试上传，不依赖发布是否成功。
- 已有完整审计优先，同一编号去重；账本与原审计日期冲突时停止。所有型号、失败和中断意图都占用共享 1,000 次上限。显式恢复、切换型号或更换证据快照不清空计数。
- 旧流程成功完成的单次尝试，可从最终 draft.json 补计；旧失败或多次尝试缺少请求前账本时，不能证明完整，停止新调用。缺失、重复、过期产物，正在执行的其他模型任务或不完整分页同样停止。
- 只读 ZIP 内唯一指定 JSON，不解压或执行内容；限制下载及 JSON 大小、条目数、压缩比、路径和符号链接。校验 GitHub 提供的产物摘要。签名下载地址不输出，Authorization 只发送给 GitHub API，不转发到存储主机。
- 当前核对凭单绑定仓库、运行、尝试及 UTC 日期，初次使用须在 15 分钟内。跨 UTC 日停止请求，须重新核对。API 读取有 2,000 条严格边界，达到边界会停止而不会当作已读完；长期增长后的分页方案仍需另行扩展。
- 核对失败保存独立预算状态。首页、目录和版本页都显示“暂停调用（共享预算尚未核实）”；核对恢复后清除该阻塞。状态事件不替代研究裁决，不把旧正文或旧确认变为新通过。
