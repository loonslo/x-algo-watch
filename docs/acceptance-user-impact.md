# 用户影响优先流程验收

维护日期：2026-10-24。用户指出 V4 仍看不出普通用户会遇到的具体变化，要求优化流程及提示词。旧三角色同意仅是历史结果，不能当作新用户体验契约通过。

## 问题与实现

- 原正文以技术枚举、重构和内部实验为主题，且摘要之外不检查代码标识。新研究先完成事实机制，再筛选有用户因果链的场景，每项增加 before/after 对比，effect 解释用户可能看到或操作上的变化；无因果链的内部改动只留技术层，允许无直接用户影响。
- 所有用户字段检查代码名、协议词和研究过程词；新输出严格要求前后对比。历史 reader 继续读取，不能冒充新审核。新字段进入数字与证据投影，不放松 grounding。
- 起草及三角色共用用户影响要求，普通理解审核先检验只读正文能否复述“什么场景、以前怎样、现在怎样、对我有什么影响”，再回证据验证。不强迫每个内部改动写入 reader，不要求每个维护变化产生假设。
- 审核历史与研究状态移到折叠附录，技术导航放正文之后；用对比表直观呈现同一场景的前后差异。旧页重排只改变展示，不人工重写旧研究。
- 长规则表改为完整 JSON 精确差集，排除行政到期与旧事实不匹配混入本次源码变化。只优先收录当前改动或直接参数引用的核心实现，减少无关视频组件占据上下文导致只剩一份 diff 的问题。仍不执行上游代码，不修改人工登记或正式速报。
