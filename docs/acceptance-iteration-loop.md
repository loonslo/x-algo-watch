# 可恢复循环修订验收

日期：2026-10-22。用户要求在固定双层输出协议和三个审核角色基础上循环修订；暂停必须有恢复路径，不能保存后就结束任务。

## 实现与边界

- `iteration.py` 管理候选、问题清单、暂停与恢复，`drafting.py` 继续负责免费调用、本地结构/证据校验、阶段缓存和共享预算；`research.py` 再校验持久化历史与最终裁决。没有引入新框架。
- 默认 V1–V5，每次修订重新执行综合机制、事实遗漏、读者理解三个角色，全部通过才生成待确认正文。固定 `openrouter/free`、每日 1,000 次，真实响应型号可相同。
- 超时/限流等失败不消耗修订次数，现有定时或手动任务从缺少阶段继续；本次运行时间达到边界同理。每阶段累计三次接口失败或两次无效输出后等待明确处理，避免无限重试。
- 本批候选上限或连续两次可识别停滞会暂停。指定单个研究提交并勾选工作流 `resume_iterations`（本地 `--resume`）后开启新批次，保留候选历史和日预算。
- 证据未知不要求猜答案；修订可撤回无依据的影响结论、降低确定性或明确未知，仍须重新审核。当前模型不能自行浏览或扩展证据；若关键材料确实缺失，需要只读补充可信上下文后重新研究。
- 三角色意见不作多数票。事实质疑需回到原证据；问题清单是追踪工具，不冒充自动语义仲裁。相同问题文字/字段/证据及不变稿件可触发停滞；同义改写未必识别，因此同时保留候选硬边界。
- 审阅双页展示进度、每版结果、问题和恢复条件；公开正文仍按审核门槛控制。未完成的新研究不抹去旧完整研究。正式速报未自动确认，历史调用和手册未改写。
