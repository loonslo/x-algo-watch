日期：2026-10-22。用户明确更正：核心是模型结合项目推测推荐算法机制的变化，版本目录只是阅读入口；固定模板不满足需求。

## 当前实现

- project_evidence 从 Git 对象读取：项目架构、多个子系统的前后差异、核心实现、参数在其他文件的引用窗口。只读、不 checkout、不执行上游；文本总量限定为 85000 字符，逐项注明截断、来源提交与行号，列出覆盖范围。不宣称读完整个仓库。
- 整个版本为一个研究对象。模型输出机制前后变化、具体影响假设、推断依据、置信度、成立条件、替代解释、验证方法及创作者含义。提示词要求积极进行有依据的推断，不能用泛泛“先观察”代替分析；也不能因名字是 FairShare 就猜成账号间平均流量。
- 使用已选定的固定 MiniMax 免费型号，两个提示词、两次调用复核。复用数字/名字/路径校验、敏感内容拦截、一次纠错、共享每日 50 次上限和缓存。每轮最多 3 个版本，超时或额度不足保留已通过阶段，下轮继续。
- 模型研究直接显示在独立版本文件，标为推测、尚未人工确认；复核分歧同时展示，未完成不展示半份未经复核的分析。固定模板收进折叠证据区域；没有模型输出的版本标待研究，不能再宣称“50 个版本已解读”。
- 正式 digest 仍须所有者确认，并绑定具体 research_id；旧速报已确认不能冒充新项目研究已确认。确认后保留所有者改稿，不重复展示原模型正文。
- 研究队列独立于红橙通知，可覆盖灰黄版本的逻辑变化。历史批量研究不批量创建通知 Issue。新版本自动准备上下文，也可用 research_commit / research_all 补写已有完整迭代，均不推进检测成功进度。
- 模型实际读取的 49 份历史上下文已准备，另 1 份为起始基线。源码中的联系地址隐去并记录标记，Python 装饰器保持原义；不是从本机私密目录取得资料。
