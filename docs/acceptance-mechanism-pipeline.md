# 分任务证据与独立机制阶段验收（集成前历史记录）

维护日期：2026-10-28。本文件记录上一轮独立模块阶段；当前集成状态以 acceptance-integrated-research.md 为准，不把下方未接入描述当作最新状态。环境：Windows / Python 3.14.0。目标仍为第二至第五步全部接通，不以新增模块或测试通过代替最终内容质量。

## 当前实现边界

新增 research_plan.py 通过 Git 对象构建全量变化清单，不限于旧证据包的 16 个文件。文件记录 prepared、needs_context 或 excluded 及理由；research_state 明确为 not_researched。小文件提供完整前后实现，大文件按真实 diff 区段拆成两侧源码窗口，保留行号、对象版本和摘要，不静默裁剪。按目录形成调度分组，不能把目录名当成机制结论。引用检索在两个版本上执行，达到命中上限、缺少定义或未找到引用时明确留缺口；这不是完整静态调用图。

用途根据测试路径、mock 标记、示例和说明分类，普通源码默认 unknown，不能凭路径宣称生产可达。原始 mock value 注释保留并标记，具体生产路径仍需结合调用代码研究。任务内合并小片段以控制调用数量，保留每个原始区段到新引用编号的映射。共享架构和流水线材料单列。

supplement_plan 按问题编号、精确前后版本、路径及有界行号读取补证，生成带 parent_plan_id 的新快照，不覆盖旧材料。文件缺失、越界或过大请求不猜填。快照按任务分文件保存，manifest 最后写入；读取时校验任务及整份计划摘要，损坏或不完整快照拒绝使用。07d159b 的完整计划超过旧单文件公开上限，故没有塞回旧 project-context，也没有提高旧发布上限。

新增 mechanisms.py、mechanism-analysis-v1.md 和 schemas/mechanism-research-v1.json：先独立输出机制判断，不生成 reader。结论包含环节、前后已知行为、调用入口与条件、中间结果、用户效果缺口、支持片段、反证、未知项、替代解释、验证办法及允许表达范围。精确行号与引文逐字核对，before/after 分别绑定原提交；C 编号由版本、文件和机制键生成，补证及改写可沿用身份。证据不足和证据否定严格区分，二者都不能通过增加“如果”进入用户稿。

新增 mechanism_runner.py：复用 openrouter/free，但先执行独立机制阶段。调用键绑定不可变任务及协议，完成任务可复用；所有旧角色、失败调用共用当日预算；格式两次无效或服务三次失败等待显式恢复，恢复开启新阶段代次且不清空计数。每次调用后可通过 persist 回调立即保存审计，实际返回型号及 usage 留痕。mechanisms_prepared 不等于审核通过或可发布，当前没有生成正式 digest 的能力。

新增 revision_audit.py：比较具体 JSON 字段，按 C 编号对齐机制结论；记录问题新增、继续出现、精确匹配回退及未再提出。没有关闭理由时保留 null，不补造理由；旧审核按原文匹配不能识别全部同义问题。
